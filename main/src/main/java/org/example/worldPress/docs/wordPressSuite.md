# Тест сьют: WordPress REST API
Набор тестов для проверки базового функционала работы
с постами и комментариями через WordPress REST API
---

## Чек-лист
- **1. Создание поста**
- **2. Изменение существующего поста**
- **3. Удаление существующего поста**
- **4. Создание комментария к существующему посту**
- **5. Изменение существующего комментария**
- **6. Удаление существующего комментария**

## Тест-кейсы: Posts

### D1-P-CR1: Создание поста (Позитивный)
**Предусловия:**
- Иметь валидные учетные данные (логин/пароль) для тестирования.
- Пользователь авторизован (учетные данные передаются через Basic Auth).

**Шаги:**
1.  В теле запроса установить параметры `title` и `content` (любые валидные значения).
2.  Отправить **POST**-запрос на эндпоинт `/wp/v2/posts`.

**Ожидаемый результат:**
- **Код ответа:** `201 Created`
- **Тело ответа:** JSON-объект, содержащий параметры `title` и `content`,
значения которых совпадают с введенными на шаге 1.
---

### D1-P-CR2: Создание поста (Негативный)
**Предусловия:**
- Иметь валидные учетные данные (логин/пароль) для тестирования.
- Пользователь авторизован (учетные данные передаются через Basic Auth).

**Шаги:**
1.  Отправить **POST**-запрос на эндпоинт `/wp/v2/posts` без тела запроса

**Ожидаемый результат:**
- **Код ответа:** `400 Bad Request`
- **Тело ответа:** JSON-объект с параметром `message`,
содержащим текст: `"Содержимое, заголовок и отрывок пусты."`
---

### D1-P-CH1: Изменение существующего поста
**Предусловия:**
- Иметь валидные учетные данные (логин/пароль) для тестирования.
- Пользователь авторизован (учетные данные передаются через Basic Auth).

**Шаги:**
1. В теле запроса установить параметры `title` и `content` (любые валидные значения).
2. Отправить **POST**-запрос на эндпоинт `/wp/v2/posts`.
3. Изменить созданный пост, отправив **POST**-запрос на `/wp/v2/posts/<id>`
   (где `<id>` — сохраненный ID) с новыми значениями для параметров `title` и `content`.

**Ожидаемый результат:**
- **Код ответа:** `200 OK`
- **Тело ответа:** JSON-объект с параметрами `title` и `content`,
значения которых совпадают с новыми значениями из шага 3.
---

### D1-P-DEL1: Удаление поста 
**Предусловия:**
- Иметь валидные учетные данные (логин/пароль) для тестирования.
- Пользователь авторизован (учетные данные передаются через Basic Auth).

**Шаги:**
1. В теле запроса установить параметры `title` и `content` (любые валидные значения).
2. Отправить **POST**-запрос на эндпоинт `/wp/v2/posts`.
3. Удалить пост, отправив **DELETE**-запрос на эндпоинт `/wp/v2/posts/<id>`.

**Ожидаемый результат:**
- **Код ответа:** `200 OK`
- **Тело ответа:** JSON-объект с параметром `status`, значение которого равно `"trash"`.

## Тест-кейсы: Comments

### D1-C-CR1: Создание комментария (Позитивный)
**Предусловия:**
- Иметь валидные учетные данные (логин/пароль) для тестирования.
- Пользователь авторизован (учетные данные передаются через Basic Auth).

**Шаги:**
1.  Создать опубликованный пост (POST `/wp/v2/posts`) с параметрами:
    - `title` и `content` = любое значение
    - `status` = `publish`
2.  Создать комментарий к этому посту (POST `/wp/v2/comments`) с параметрами:
    - `post` = `<id_поста_из_шага_1>`
    - `content` = любое значение

**Ожидаемый результат:**
- **Код ответа:** `201 Created`
---

### D1-C-CR2: Создание комментария (Негативный)
**Предусловия:**

- Пользователь авторизован (учетные данные передаются через Basic Auth).

**Шаги:**
1.  Создать опубликованный пост (POST `/wp/v2/posts`) с параметрами:
    - `title` и `content` = любое значение
    - `status` = `publish`
2.  Создать комментарий к этому посту (POST `/wp/v2/comments`) с параметрами:
    - `post` = `<id_поста_из_шага_1>`
    - Без параметра `content`

**Ожидаемый результат:**
- **Код ответа:** `400 Bad Request`
- **Тело ответа:** JSON-объект с параметром `massage`: `"Неверное содержание комментария."`
